# OPENCLAW Email Agent

OpenClaw-native Gmail triage pipeline: classify inbound mail (LLM or keyword), route to departments, send via **gog**, and archive runs to **Azure Blob Storage**.

Designed to run under **`openclaw-gateway.service`** on Ubuntu/WSL with hook transform `email-pipeline-triage.mjs` (generated by this repo).

Repository: [github.com/Satyam-affine/OPENCLAW-EMAIL-AGENT](https://github.com/Satyam-affine/OPENCLAW-EMAIL-AGENT)

---

## Quick start (Ubuntu / WSL — fresh terminal)

```bash
# 1) Go to this project (adjust path if you cloned elsewhere)
cd ~/.openclaw/workspace/UL\ USECASE

# 2) Python venv + dependencies
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3) Configure secrets (copy template, then edit)
cp .env.example .env
nano .env

# 4) Sync OpenClaw Gmail hook + transform into ~/.openclaw/
python3 pipeline.py setup-gateway

# 5) Restart gateway (requires OpenClaw installed + systemd user unit)
systemctl --user daemon-reload
systemctl --user restart openclaw-gateway.service
systemctl --user status openclaw-gateway.service

# 6) Verify hook wiring
python3 pipeline.py verify-gateway
```

## Environment prerequisites

| Requirement | Notes |
|-------------|--------|
| [OpenClaw](https://github.com/openclaw/openclaw) | Gateway on `127.0.0.1:18789`, `hooks.gmail` enabled |
| **gog** | Gmail OAuth + `gog gmail watch` (managed by gateway) |
| **Azure OpenAI** | When `CLASSIFICATION_ENGINE=llm` |
| **Azure Blob** | Optional; `AZURE_BLOB_*` for archival to container `openclaw-ul` |

Do **not** set `OPENCLAW_SKIP_GMAIL_WATCHER=1`. Do **not** run a separate legacy bridge on another port.

---

## Flow

```
Gmail → gog watch → POST /hooks/gmail
  → email-pipeline-triage.mjs (noop / dedup / ingest)
  → pipeline.py ingest
  → classify + multi-route
  → DISPATCH_STRATEGY=direct → gog gmail send per department
  → Azure Blob: YYYY-MM-DD/email_<message_id>/…
```

With **`DISPATCH_STRATEGY=delegate`**, the hook may spawn **triage-coordinator** and specialist agents instead of direct send.

## Common commands

```bash
cd ~/.openclaw/workspace/UL\ USECASE
source .venv/bin/activate

# Regenerate hook after editing pipeline.py
python3 pipeline.py setup-gateway
systemctl --user restart openclaw-gateway.service

# Live logs
journalctl --user -u openclaw-gateway.service -f

# Manual dispatch from saved payload
python3 pipeline.py dispatch --json dispatch_queue/gmail-<id>-1-<category>.payload.json

# Test Azure archive (no email send)
python3 pipeline.py test-blob-upload --pdf /path/to/sample.pdf

# Multi-route simulation
python3 pipeline.py simulate-triage

# Optional routing dashboard
python3 pipeline.py dashboard
```

## Repo layout

| Path | Purpose |
|------|---------|
| `pipeline.py` | Ingest, routing, dispatch, gateway setup, blob archive |
| `llm_router.py` | Structured LLM classifier (Pydantic) |
| `gmail_routing.json` | Department rules + recipients |
| `.env` | Secrets (gitignored) — use `.env.example` as template |

Runtime dirs (`dispatch_queue/`, `attachments/`, etc.) are created locally and **gitignored**.

---

## Routing

Edit `gmail_routing.json` for categories, keywords, and recipient emails. Re-run `setup-gateway` after routing-only changes is not required; restart gateway only if hook source changed.
